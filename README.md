# college-student-growth-portrait-visualization

大学生成长画像分析与可视化课程设计，包含数据采集、分析与交互式可视化功能。

## 需求分析

画像系统的核心流程为“数据采集 → 标签提取 → 标签体系 → 画像生成 → 可视化与服务”。需求分析不从“有什么数据”出发，而从“谁要做什么决策”出发，围绕学生、教师、企业三类主体及系统合规约束展开。

### 学生端：自我导航
- 能力全景：以雷达图呈现多维能力水平与短板，而非单一综合评分。
- 成长时间线：记录项目、竞赛、实习等关键事件，形成入学到毕业的纵向成长曲线。
- 岗位对标：输入目标岗位后，逐项标注“能胜任 / 需补强 / 无证据”，并推送补强建议。
- 隐私控制：学生自主决定哪些能力标签对企业可见。

### 教师端：过程诊断与干预
- 双层画像：先看班级/专业的能力分布与共性短板，再下钻到个体。
- 学业预警：基于行为与时间序列提前识别有断档风险的学生。
- 教学归因：将能力短板回溯到课程、知识点或教学环节。
- 干预追踪：记录帮扶措施并追踪效果，避免预警流于形式。

### 企业端：能力证据
- 标签映射：将岗位需求结构化为能力标签，与学校标签体系建立可计算映射。
- 证据呈现：每项能力标签附带课程项目、竞赛、实习等具体证据来源。
- 群体趋势：提供届别能力对比与培养方向重合度，个体画像仅限授权使用。
- 反馈闭环：企业检索与匹配数据反向输入学校，辅助培养方案调整。

### 系统与合规
- 数据分级：明确核心必需、可选增强与不应采集的数据，遵循最小必要原则。
- 可解释可申诉：标签来源可解释，并保留错误标签申诉通道。
- 算法公平：设定公平性审查节点，防范对特定群体的系统性偏差。

### 整合与 MVP
按“分主体需求清单 → 冲突识别与优先级裁决 → MVP 界定”三步落地：
- 学生端：能力雷达图 + 成长时间线 + 目标岗位对标（1—2 个试点专业）。
- 教师端：群体能力分布 + 学业预警列表 + 干预记录。
- 企业端：暂不开放个体画像，先做岗位能力模型与学校标签体系的映射验证。
